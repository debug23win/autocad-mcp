# Первый пользовательский прогон новых сценариев

**Текущий итог после отдельного исправленного T06: все шесть сценариев подтверждены по приложенным чтениям.** T01–T05 не повторялись. Это первый прогон плюс отдельное продолжение, а не один непрерывный прогон без ошибок. Первоначальный отказ подготовки T06 сохранён ниже.

Источник: предоставленный пользователем экспорт `cad-mcp-answer.docx`. CAD MCP 0.11.3-preview; AutoCAD `26.0s (LMS Tech)`, соответствующий AutoCAD 2027; миллиметры, Model, WCS. Фактического доступа к этой AutoCAD-сессии у проверяющего нет: выводы ниже основаны на приложенных ответах инструментов, а не на повторном живом запуске.

Грейдер после нормализации формата подтвердил T01–T05; T06 не прошёл критерии, поскольку ответы страниц отсутствуют. Это не означает дефект пагинации. Агент добавил отсутствовавший в исходном задании критерий `type_counts: {"Point":12}`. `Reader.Read` возвращает `type=DBPoint`, поэтому проверка получила actual=0 при entity_count=12 и штатно откатила транзакцию. Отдельный поиск подтвердил отсутствие точек. Исправленное продолжение: [только T06](../current-2027-t06-only.md).

Времена, приведённые в экспорте: 10.700 / 11.735 / 13.371 / 7.263 / 14.582 / 12.947 с; всего 98.325 с и 38 CAD-вызовов. Это измерения из отчёта агента, без независимого таймера; один прогон не устанавливает устойчивую производительность. Общий итог экспорта — 5 PASS, 1 FAIL подготовки, без UNKNOWN. В Model осталось 11 объектов, ещё две линии находятся в определении блока; итоговое чтение 13 живых сущностей согласуется с этим составом. DWG не сохранён, DBMOD=33.

Обнаружен дополнительный сбой автоматического превью панели: `Frame root_handle for a nested instance`. Агент не запрашивал рендер, но автоматическая проверка панели включила handles линий внутри определения блока. Это сбой формирования изображения, а не отрицание приложенных числовых чтений и не доказательство повреждения DWG. Исправление ещё требуется.

Ограничения оценки: экспорт содержит выбранные поля некоторых ответов и не содержит полного `cad_changes`; исчерпывающий аудит отсутствия всех изменений вне тестовых слоёв по нему невозможен. В evidence были оболочки `status/data`, а аргументы `*_json` представлены объектами/массивами. Для запуска существующего грейдера оболочки сняты, общие аргументы восстановлены, `*_json` закодированы строками. Значения evidence и неуспешный исход T06 не изменены. Исходный JSON, нормализованный JSON и результат грейдера сохранены локально в `artifacts/benchmarks/autocad2027-0.11.3/`; это пользовательские результаты, не результаты CI.

## Исправленный T06: отдельное продолжение

Источник: предоставленный пользователем файл `Вставленный текст.txt`. Исходные JSON трёх страниц проверены программно:

- статусы всех страниц completed, единые session/document и ревизия 2303;

- все 12 handles уникальны и точно совпадают с приложенным списком созданных handles (`342`…`34D`);
- тип DBPoint, DXF POINT, слой QA27N_PAGES; min=max каждой точки соответствует [6000+10*i,0,0], i=0..11.

T06 — PASS по этим доказательствам. Сообщены один commit с `expectations_json={"entity_count":12,"enforce":true}`, 9 CAD-вызовов и 37.129 с. Полный журнал вызовов, исходный ответ commit и ответ финального cad_verify в приложении отсутствуют; они не реконструировались. Списки handles и три страницы сохранены как `t06-corrected.handles.json` и `t06-corrected.pages.json`.

Для сводной машинной оценки взяты прежние T01–T05 и новый T06; `runs.completed.normalized.json` и `grade.completed.json` дают 6/6 пройденных сценариев по критериям грейдера. Первый неуспешный T06 и исходный отчёт не перезаписаны. Времена двух попыток не объединялись в якобы единый успешный замер. Известные сбои Redo при открытом чате, cad_outline и автоматического превью вложенных объектов этим результатом не закрываются.
