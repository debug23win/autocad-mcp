# Новые проверки AutoCAD 2027 / CAD MCP 0.11.3-preview

Пакет для одного задания в чате плагина. Это функциональная приёмка с открытыми критериями, а не слепое сравнение моделей. Все результаты подтверждаются отдельными чтениями; один только текст агента не считается доказательством.

Уже проверенное исключено: откат при enforced-критерии, резервная копия и её открытие, отказ смешанного пакета, простое создание линии/окружности и сохранение с повторным открытием DWG. Redo и `cad_outline` отложены до исправленной сборки. `cad_file_inspect` и `cad_takeoff(scope=all)` используют тот же сломанный обход листов, поэтому тоже исключены. Создание простых объектов ниже служит только подготовкой новых сценариев и отдельно не оценивается.

## Запуск одним заданием

Создайте отдельный пустой тестовый DWG в миллиметрах, перейдите на вкладку «Модель», откройте для него новый диалог CAD MCP. Вставьте целиком блок ниже. По ходу прогона не редактируйте DWG вручную. Завершённые проверки старого набора повторять не нужно.

```text
Выполни пакет из шести НОВЫХ функциональных проверок CAD MCP 0.11.3-preview в текущем закреплённом тестовом DWG. Выполняй их последовательно одним заданием, без промежуточных вопросов.

Подготовка: проверь cad_context, document_id, миллиметры и пространство Model. Прочитай cad_edit_help и cad_catalog. Используй только слои QA27N_POLY, QA27N_TEXT, QA27N_BLOCKS, QA27N_TRANSFORM, QA27N_TABLES, QA27N_PAGES и определение блока QA27N_BLOCK_DEF. Если любое из этих имён уже существует, остановись до правок и сообщи, что нужен новый тестовый DWG. Не меняй единицы и существующие объекты. Зафиксируй начальную ревизию и исходное число объектов.

Каждый cad_edit получает уникальный operation_id, свежую expected_revision и только операции из справки. Подготовительные линии и другие примитивы — не отдельные тесты. Не вызывай cad_outline, cad_file_inspect, cad_takeoff со scope=all, cad_lisp, cad_render; не проверяй Undo/Redo, сохранение, checkpoint и запрет смешанных пакетов. Не создавай листы и файловые экспорты, не сохраняй DWG автоматически. Штатные автоматические checkpoint плагина не отключай; они не являются отдельной проверкой этого пакета.

T01 — замкнутая полилиния и ведомость площадей.
На QA27N_POLY создай одну замкнутую полилинию с вершинами [1000,1000], [1200,1000], [1200,1100], [1000,1100]. Отдельным cad_entity_get проверь closed=true и четыре вершины. Через cad_takeoff(scope=model, layers_json=["QA27N_POLY"], include="lengths,areas") проверь один контур, длину 600 и площадь 20000. Допуск чисел 0.000001. Сохрани ответ takeoff как evidence.takeoff для T01.

T02 — точная замена Unicode-текста.
На QA27N_TEXT создай две TEXT на [2000,0] и [2000,100] и одну MTEXT на [2000,200], высота 10. Содержимое каждой: "Труба Ø108". Одним text_replace замени только на этом слое Ø108 на Ø114. Через cad_search(scope=model, layer=QA27N_TEXT, text="Ø108", limit=500) проверь 0 объектов; аналогичный поиск Ø114 должен вернуть 3 объекта. Отдельным чтением проверь полный текст всех трёх и сохранность типов: два DBText и один MText. Запиши сырые ответы поиска в evidence.old и evidence.new.

T03 — определение блока и вставки.
На QA27N_BLOCKS подготовь две линии: [3000,0]–[3100,0] и [3000,0]–[3000,50]. Создай QA27N_BLOCK_DEF из их handles с базовой точкой [3000,0]. Создай две вставки блока на этом же слое: в [3500,0] без поворота и в [3700,0] с поворотом 90 градусов, масштаб 1. Исходные линии оставь. Проверь две вставки по эффективному имени через cad_takeoff(scope=model, layers_json=["QA27N_BLOCKS"], include="blocks") и через cad_search с expand_blocks=true: каждый блок раскрывается в две линии с корректными WCS-положениями. Запиши ответ takeoff в evidence.takeoff; handles и чтения вложенных линий приложи отдельно.

T04 — копирование, поворот, масштаб и удаление только тестового исходника.
На QA27N_TRANSFORM создай линию [4000,0]–[4100,0]. Скопируй её на [0,200], поверни копию на 90 градусов вокруг [4000,200], затем увеличь в 2 раза относительно той же точки. Исходную тестовую линию перемести на [50,0], отдельно проверь её новые концы [4050,0] и [4150,0], затем удали ТОЛЬКО этот исходник. Копия должна остаться с концами [4000,200] и [4000,400], длина 200. Подтверди отсутствие исходника и свойства копии отдельными чтениями. cad_takeoff(scope=model, layers_json=["QA27N_TRANSFORM"], include="lengths") должен вернуть одну линию, суммарную длину 200. Запиши его ответ в evidence.takeoff, ответы чтения копии/исходника — отдельно. Допуск чисел 0.000001.

T05 — формулы и зависимость двух нативных таблиц.
На QA27N_TABLES создай исходную таблицу 3x3 в [5000,0]: A1=4, B1=2.5, C1 формула =A1*B1. Создай зависимую таблицу 2x2 в [5200,0]; A1 — формула ={{mass}}*2, reference mass указывает на C1 исходной таблицы. Используй table_target в том же пакете либо фактический handle из результата. Отдельным cad_table_get проверь исходное C1=10 и зависимое A1=20. Измени только A1 исходной таблицы на 6. Повторным cad_table_get проверь C1=15 и зависимое A1=30. Читай числовые value, не оценивай только строку формулы. Запиши сырые чтения как evidence.source_before, dependent_before, source_after, dependent_after. Допуск 0.000001.

T06 — пагинация поиска без потерь и дублей.
На QA27N_PAGES создай 12 точек: [6000+10*i,0,0], i=0..11. Для этого cad_edit передай ровно expectations_json={"entity_count":12,"enforce":true}, не добавляй type_counts или другие критерии. В readback нативное имя точки — DBPoint; это отличается от имени операции point и DXF-имени POINT. Через cad_search(scope=model, layer=QA27N_PAGES, type=POINT, limit=5, offset=0) прочитай страницы, каждый раз используя возвращённый pagination.next_offset. Ожидаются страницы по 5, 5 и 2 объекта; последняя без next_offset. Сравни множество всех handles со множеством 12 созданных точек: без пропусков и дублей. Повтор или отсутствие продвижения next_offset — FAIL; не зацикливайся. Сохрани сырые страницы как evidence.page1, page2, page3 и полный список handles.

Обработка ошибок: по каждому сценарию PASS допустим только при наличии всех отдельных чтений и совпадении значений. При явной терминальной ошибке отметь FAIL, сохрани точные code/message и перейди к независимому сценарию. Если подготовка не удалась, зависимые шаги отметь SKIPPED с причиной. Не подбирай другой способ ради PASS, не повторяй правку с новым operation_id, не заменяй сбой AutoLISP. При timeout/неизвестном исходе читай cad_operation_status с прежним id; если исход остался неизвестен, прекрати ВСЕ следующие записи, сохрани отчёт с UNKNOWN и безопасно доступные чтения. При смене сессии/документа также останови записи. Не считай partial/усечённый ответ доказательством отсутствия объекта.

В конце выдай одну таблицу: ID | PASS/FAIL/SKIPPED/UNKNOWN | ожидаемое | фактически прочитанное | handles/operation_id | код ошибки. Следом — счётчики результатов, фактическое число вызовов CAD-инструментов, измеренное время по каждому сценарию и общее время. Если измерение времени недоступно, напиши "не измерено", не оценивай длительность на глаз. Не запрашивай отдельные рендеры для отчёта.

Затем выведи JSON runs: по одной записи на T01..T06 с task, calls (tool/arguments/status/error_code/result), final_text, asked_user=false и evidence из реальных отдельных чтений. Не подставляй ожидаемые значения вместо фактических ответов. В поисковых evidence сохрани оболочку result.entities и result.pagination, как она пришла от CAD. Добавь поле release="0.11.3-preview" и версию AutoCAD из контекста. DWG оставь открытым без автоматического сохранения и уборки: тестовые объекты нужны для разбора результатов.
```

## Оценка

Результат пакета — шесть отдельных статусов. `SKIPPED` и `UNKNOWN` не являются успехом. Полностью пройденный пакет: 6 PASS, без FAIL/SKIPPED/UNKNOWN. Для сравнения производительности берите одинаковый исходный пустой DWG, версию AutoCAD, модель и режим; время и число обращений — наблюдаемые показатели, без неподтверждённых порогов.

`current-2027-new-tests.tasks.json` содержит дополнительные машинные проверки числовых/структурных evidence для существующего `--grade`. Проверки WCS вложенных блоков, точных строк текста и уникальности handles из сценария всё равно должны быть отражены в отчёте: этот JSON не заменяет их. Для T05 evidence — ответы `cad_table_get`; для T06 — три исходных ответа поиска. Не запускайте `--capture-evidence` на текущей сборке: он безусловно вызывает уже известный неисправный `cad_outline`. Передавайте грейдеру сохранённые прямые ответы чтения.

```powershell
CadMcp.Host.exe --grade current-2027-new-tests.tasks.json runs.json
```

Если чат не может записать `runs.json`, сохраните его JSON-блок вручную. Машинная оценка возможна только для записей с реальными evidence; пустые заготовки результата намеренно не приложены. [Первый пользовательский прогон и завершение T06](results/2026-11-09-autocad2027-0.11.3.md) записаны отдельно; уже выполненные проверки повторять для этого отчёта не требуется.
