# Завершение только T06 после первого прогона

T01–T05 уже пройдены, повторять их не нужно. В первом T06 подготовка откатилась с `ACCEPTANCE_FAILED` из-за добавленного агентом `type_counts: {"Point":12}`. Пагинация ещё не проверена. Сценарий ниже намеренно задаёт исправленный критерий; неизвестную операцию он не повторяет.

Вставьте блок целиком в чат текущего тестового DWG:

```text
Выполни только исправленный T06. T01–T05 и другие проверки не повторяй, существующие объекты не меняй.

1. Проверь актуальный закреплённый document_id, миллиметры, Model. Через cad_catalog и поиск убедись, что слой QA27N_PAGES и его объекты отсутствуют. Если остались — остановись до правок и сообщи об этом.
2. Сделай ровно один cad_edit с новым уникальным operation_id и свежей expected_revision: слой QA27N_PAGES и 12 операций point с координатами [6000+10*i,0,0], i=0..11. Передай РОВНО expectations_json={"entity_count":12,"enforce":true}. Не добавляй type_counts, bounds_size и другие критерии; имя типа в readback — DBPoint, не Point. Сохрани множество 12 handles из результата.
3. Только после успешного commit вызови cad_search с options_json={"scope":"model","layer":"QA27N_PAGES","type":"POINT","limit":5,"offset":0}. Читай следующие страницы по фактическому pagination.next_offset. Ожидается 5/5/2, next_offset 5, затем 10, затем отсутствует. Проверь, что 12 handles уникальны и их множество в точности совпадает с созданными точками. Если next_offset повторяется или не продвигается, зафиксируй FAIL без цикла.
4. Выдай одну строку итогов T06, все три сырых ответа страниц, список созданных handles, список найденных handles и точные коды ошибок, если они возникнут. Значения не подставляй из ожиданий. Измеренное время и число CAD-вызовов укажи отдельно; если времени нет, напиши «не измерено».

Не вызывай cad_outline, cad_file_inspect, cad_render, cad_lisp. Не сохраняй DWG и не делай очистку. При явном отказе отметь ошибку подготовки и пропуск пагинации; автоматически не повторяй правку. При неизвестном исходе читай только cad_operation_status с прежним operation_id и останови дальнейшие записи. Этот тест не меняет ранее полученные результаты T01–T05.
```
