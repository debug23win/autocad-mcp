# Проверка

Как проверяется текущая версия. Что проверялось в каждом выпуске — в [CHANGELOG.md](../CHANGELOG.md).

## Автоматические тесты

`scripts/build.ps1`, затем `scripts/test.ps1` (или `dotnet test tests/CadMcp.Tests`). Тесты xUnit в `tests/CadMcp.Tests` проверяют:

- обмен кадрами через именованные каналы, broker, его запуск, остановку с завершением текущих запросов и замену устаревшей версии;
- журнал операций, восстановление потерянного ответа без повторной правки, архив больших результатов, изоляцию отмены;
- разбор планов правок и критериев приёмки, проверку геометрии, калибровку изображений, обёртку AutoLISP;
- историю и вложения чата, отображение Markdown и экспорт в Word;
- протоколы Codex и Claude Code на подставных процессах из `tests/CadMcp.TestCli`: потоковый текст, дополнения во время хода, отмену, выбор модели, отказ на интерактивные запросы, длину командной строки;
- настоящий MCP SDK через stdio собранного `CadMcp.Host`: список инструментов, их классификацию «только чтение», закрепление за чертежом, ограничения помощников.

AutoCAD, настоящие CLI и модели в этих тестах не запускаются. Тесты выполняются по одному: они запускают процессы и broker и измеряют время.

## Проверка сохранности DWG после изменений правил транзакций

Автоматические тесты проверяют сохранение завершённой квитанции при ошибке записи и последующем вытеснении кеша, а также запрет смешанных пакетов с операциями вне транзакции. Они не запускают AutoCAD и не доказывают нативный откат.

На Windows в установленном AutoCAD, используя только отдельный тестовый DWG:

1. Создайте обычным пакетом геометрию с заведомо невыполнимым enforced-критерием. Проверьте отсутствие созданных объектов после ошибки и после повторного открытия DWG.
2. Отправьте `layout_create` вместе с `line` в обоих порядках. Оба запроса должны вернуть `SINGLE_OPERATION_REQUIRED`, не создавая ни листа, ни линии.
3. Выполните отдельный `layout_create`. Проверьте наличие и открытие `checkpoint.path`, совпадение его SHA-256 с квитанцией и отсутствие нового листа в копии. Копию открывайте отдельно.
4. Для отдельной операции вне транзакции задайте невыполнимый enforced-критерий. Проверьте, что ошибка содержит `partial_changes_possible` и путь к копии; установите фактическое состояние DWG без автоматического повтора.
5. В изолированном тестовом профиле сделайте каталог recovery недоступным для записи. Новая операция вне транзакции должна завершиться `CHECKPOINT_FAILED` до изменения DWG. Верните доступ после проверки.
6. Проверьте Undo/Redo и повторное открытие тестового DWG после успешного обычного пакета. Между Undo и Redo завершите команду Undo, оставьте чат открытым не менее 10 секунд: должны успеть пройти фоновые опросы контекста и открытых DWG. После опросов Redo должен вернуть весь пакет. Повторите с закрытым чатом для сравнения. `CADMCPGUISTABILITY` дополнительно выполняет явные опросы `cad_context`, `cad_catalog`, `cad_snapshot` и списка DWG между отдельными командами Undo и Redo, в том числе для связанных таблиц. Отдельно повторите проверки для установленного AutoCAD 2027, Civil 3D/Map 3D; результат базового AutoCAD 2025 не подтверждает их поведение.

Чтение объектов `ForRead` не требует блокировки документа; [документация Autodesk по lockDocument](https://help.autodesk.com/cloudhelp/2026/ENU/OARX-RefGuide/files/OARX-RefGuide-AcApDocManager__lockDocument_AcApDocument__AcAp__DocLockMode_ACHAR__ACHAR__bool.html) также указывает, что блокировка считается началом команды. Поэтому обычные операции чтения выполняются на CAD-потоке без блокировки записи. Правки и `cad_edit_preview` сохраняют блокировку записи. Для этой коррекции требуется живая проверка Redo; сборка и модульные тесты её не заменяют.

## CI

`.github/workflows/ci.yml` на Windows для каждого pull request и для `main`:

1. Ставит .NET 8 и .NET 10 и получает справочные сборки AutoCAD 2025 из NuGet (`scripts/autocad-references.ps1`, с проверкой SHA-256). В сборку и установщик они не попадают.
2. Восстанавливает пакеты в строгом режиме по lock-файлам.
3. Собирает все проекты из `.github/ci-projects.txt`, включая адаптеры .NET 10 и проверочные программы для AutoCAD; предупреждения считаются ошибками.
4. Запускает тесты и сохраняет результаты TRX.

## Выпуск

`.github/workflows/release.yml` собирает установщик на Windows через `scripts/build-installer.ps1`:

1. Повторяет проверки CI на коммите выпуска.
2. Скачивает официальный Codex 0.159.0 и сверяет контрольные суммы (`scripts/prepare-codex.ps1`).
3. Компилирует установщик в Inno Setup 6.3 или новее.
4. Сверяет каждый файл комплекта с манифестом.
5. Пишет `validation.json` и `SHA256SUMS.txt`.

Pull request, который меняет инструменты выпуска или версию, только собирает установщик и сохраняет его как артефакт запуска. Публикация — ручной запуск на `main` (Actions → Release → Run workflow) с версией из `Directory.Build.props`: появляется pre-release `v<версия>`. Его описание берётся из раздела этой версии в CHANGELOG. Проверки в AutoCAD workflow не выполняет; их итог дописывается в CHANGELOG вручную.

## Проверки в AutoCAD

Выполняются вручную на компьютере с AutoCAD; рабочие чертежи не открываются.

- `tests/CadMcp.CoreProbe` и `scripts/test-autocad-core.ps1` — AutoCAD Core Console; `scripts/test-dwg-read.ps1` — чтение DWG.
- `tests/CadMcp.NativeProbe` и `scripts/test-autocad-gui.ps1` — GUI AutoCAD и Map 3D (`-Product MAP`).
- `tests/CadMcp.GuiProbe` — команды для нескольких открытых DWG и чтения листов (загружается через NETLOAD).
- `tests/CadMcp.ChatPanelProbe` — панель чата WPF без AutoCAD.
- [Контрольный список живой проверки](live-checklist.md).

Для регрессий перевода и замены текста 0.11.1 после сборки `tests/CadMcp.CoreProbe`:

```powershell
./scripts/test-autocad-core.ps1 -TextRegressionOnly -DynamicTextFixture 'C:\Program Files\Autodesk\AutoCAD 2025\Sample\ru-RU\Dynamic Blocks\Annotation - Metric.dwg'
```

Это отдельный скрытый Core Console с временным DWG и профилем. Штатный пример AutoCAD читается без записи и клонируется в тестовый чертёж. Для другой локализации укажите путь к локальному примеру с динамическими блоками. Отсутствие такого примера считается невыполненной проверкой, а не успехом. Список проверок и ошибка сохраняются в `result.json` каталога пробы; успешный результат копируется в `artifacts/core-probe-latest.json`.

Для аварий 0.11.2 после сборки `tests/CadMcp.NativeProbe` (нужен установленный AutoCAD 2025 или 2026):

```powershell
./scripts/test-autocad-gui.ps1 -Command CADMCPSHEETREGEN -TimeoutSeconds 1200
```

Проба по шагам повторяет пакет листа А1 в новых чертежах: рамка, таблица, межтабличная формула, примечания, всё вместе, после предпросмотра, `render_then_edit` и `frame_explode`. Каждый шаг пишется в `.progress` до выполнения. `-Variants` выбирает варианты, `-Plan` повторяет план из квитанции операции. Результат сохраняется в `artifacts/gui-probe-latest.json`.

## Проверки с настоящими CLI

Добровольные и по подписке; используют записывающий CAD-фикстур, чертежи не меняются. После сборки Release из корня репозитория:

- `CadMcp.TestCli.exe --live-subagent-test codex|claude <cli>` — помощник работает только на чтение;
- `CadMcp.TestCli.exe --live-codex-model-test <cli> [--resume-conversation <id>]` — выбор модели и сохранение диалога;
- `CadMcp.TestCli.exe --live-codex-approval-test <cli>` — разрешения CAD-инструментов в Codex;
- `CadMcp.TestCli.exe --cli-config-check <cli>` — Codex принимает конфигурацию MCP и ролей помощников.

## Оценка агентов

Стенд в `benchmarks/` оценивает агента по фактическому состоянию DWG после прогона: задачи со скрытыми проверками, жёсткие провалы (ложный успех, удаление без запроса, правки вне задачи, выдуманный инструмент, запись без данных, повтор неизвестной правки, обход отказа от AutoLISP), три прогона на задачу, проверка грейдера «пустым» прогоном и сравнение с прошлым выпуском. Порядок — в [benchmarks/README.md](../benchmarks/README.md); команды `CadMcp.Host.exe --capture-evidence`, `--grade`, `--grade-selfcheck`.
