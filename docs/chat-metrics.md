# Время и токены в ответах

По умолчанию показываются понятные комментарии основного агента о чтении, изменениях и проверке. Переключатель «Показывать ход работы» отключает запись новых комментариев. Переписка помощников и технические журналы скрыты; кнопка копирования копирует итоговый ответ. Провайдер, модели и уровни рассуждений Codex/Claude сохраняются отдельно и применяются при следующем запуске и в новых вкладках.

В конце ответа CAD MCP выводит время задачи и токены из событий CLI. Таймер начинается при отправке запроса и останавливается после проверки результата плагином, включая автоматическое превью. Ожидание провайдера, подтверждений и проверки чертежа входит во время. Дополнения, отправленные во время работы, относятся к той же задаче; итоговый блок появляется в её последнем ответе.

Для Codex показана разница накопительных счётчиков основного агента между началом и концом текущей задачи. История возобновлённого чата вычитается по событию replay; без этой исходной точки расход не вычисляется. Счётчики помощников не включены. Повторное событие usage обновляет значение, а не прибавляет его. Кешированные входные токены и токены рассуждений уже входят в основные счётчики Codex и повторно не добавляются.

Для Claude показано поле `usage` последнего события `result`, с явной подписью «последний результат Claude». Вход включает `input_tokens`, `cache_read_input_tokens` и `cache_creation_input_tokens`; выход — `output_tokens`. При нескольких результатах из-за дополнений эти значения не складываются, поскольку провайдер может передавать накопительные данные.

При отсутствии достоверных счётчиков написано «нет данных». При ошибке или остановке доступные значения помечены как неполные. Это не оценка стоимости и не число токенов только видимого текста ответа. Бенчмарк запускает фиксированные операции без модели и показывает 0 токенов.

Протокол Codex сверён со схемой закреплённой версии CLI [0.159.0](https://github.com/openai/codex/blob/rust-v0.159.0/codex-rs/app-server-protocol/schema/typescript/v2/ThreadTokenUsage.ts) и механизмом [replay при возобновлении](https://github.com/openai/codex/blob/rust-v0.159.0/codex-rs/app-server/src/request_processors/token_usage_replay.rs).


Остаток лимитов Codex берётся из account/rateLimits/read и уведомлений account/rateLimits/updated. Показываются фактический оставшийся процент, продолжительность окна (например 5 ч / 7 дн) и время сброса в локальном времени Windows. Состояние обновляется при отправке запроса. При отсутствии данных написано «нет данных»: остаток не вычисляется из токенов, а процент не является обещанием доступности модели.

Codex ограничивает запуск задачи 90 секундами, а полное отсутствие событий во время работы — 5 минутами. Любая активность протокола, включая скрытые служебные сообщения, обновляет индикатор связи. По тайм-ауту процесс CLI останавливается без повторной отправки правки; уже принятые AutoCAD операции требуют проверки по квитанциям. Это не принудительное прерывание CAD-команды.
