# Доступность нескольких DWG

`cad_runtime_status.document_availability` показывает document_id, read_available, write_available, command_in_progress, reason и observed_at закреплённого DWG. Ответ берётся из снимка без ожидания CAD UI thread. Это последнее наблюдение, а не резервирование: worker повторяет проверку перед выполнением.

Очередь сохраняет порядок одного документа и выбирает готовые запросы других DWG, обходя занятый. Свободный неактивный документ читается без переключения вкладки. Правка выполняется, когда цель свободна и AutoCAD разрешает активацию. BACTION одного чертежа больше не служит безусловной глобальной проверкой для всех запросов.

Известная недоступность отклоняет правку до принятия с DOCUMENT_BUSY. Агент проверяет доступность и свежий контекст. Панель сначала читает быстрый статус и показывает активную команду вместо ожидания чтения занятого DWG. Истёкшие/отменённые запросы не удерживают готовые обращения.

Это чередование на безопасных границах: AutoCAD API исполняется последовательно на основном потоке. Модальный диалог, выполняющийся Lisp, запрет MDI-активации и длительный kernel могут приостановить CAD-обращения всего процесса. Worker не посылает Esc и не обрывает пользовательскую команду. Модели, компиляция в host, загрузка и чтение PDF могут идти параллельно; одновременные CAD kernel-вызовы требуют отдельных AutoCAD-процессов.
