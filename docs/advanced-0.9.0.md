# Возможности 0.9.0

У каждой вкладки свой DWG, диалог, модель, рабочая папка и владелец CAD-заданий. Codex и Claude могут работать одновременно в разных вкладках. Субагенты читают документ своей вкладки; результат проверки возвращается основному агенту. Все обращения к базе AutoCAD идут последовательно на CAD-потоке. MCP host отклоняет запрос с идентификатором чужого документа, включая запрос изображения. История хранится по полному пути DWG в `%LOCALAPPDATA%/CadMcp/chat/projects`; несохранённые DWG получают отдельные идентификаторы.

«Стоп» сначала посылает отмену собственных принятых CAD-заданий, затем останавливает провайдера. Запросы других вкладок продолжаются. Отмена до выполнения не изменяет DWG; нативный пакет проверяет отмену между действиями и откатывает незавершённую транзакцию. Текущий вызов геометрического ядра не прерывается принудительно. Для уже выполняющегося AutoLISP требуется Esc. Потерянный ответ восстанавливается из журнала без повторного построения.

Перед пакетами от 25 действий, удалением, Boolean/shell, обновлением сборки и Map/LISP сохраняется копия базы через `Database.Wblock()`, с листами. Рабочее имя и DBMOD сохраняются. В `%LOCALAPPDATA%/CadMcp/recovery` остаются до десяти копий на документ в сессии и последняя фаза операции. `cad_diagnostics` в привязанном чате показывает его документ; незавершённая старая фаза означает неизвестный исход. Восстановление выполняется открытием копии отдельно, а не перезаписью рабочего DWG.

`cad_review` проверяет пересечение объёмов Solid3d, пересечение габаритов текстов, вместимость текста штатных Table и размещение объектов на бумаге. Предупреждение о пересечении может описывать намеренный стык. Содержимое вложенных блоков этим инструментом не разворачивается; его нужно читать отдельно через `cad_search` и проверять изображением. `cad_release_check` проверяет листы, внешние ссылки, шрифты, печатное устройство и обозначения штампов. Ошибки ресурсов блокируют публикацию; предупреждения требуют рассмотрения агентом. PDF проверяется строгим парсером и ожидаемым количеством страниц; ведомость показывает отсутствующие листы и SHA256. Внешний вид проверяют по отрисованному PDF.

Формулы, созданные CAD MCP, получают граф зависимостей в Xrecord и стабильные идентификаторы ячеек в их CustomData. Проверяются циклы, порядок вычисления и исчезнувшие источники. Ссылки сохраняются после вставки строк и столбцов, включая ручную вставку штатной таблицей. Удаление используемой строки/столбца через CAD MCP отклоняется. Ручное удаление или копирование идентификаторов выявляется как повреждённая ссылка. После правки источника пересчитываются зависимые таблицы; ручные изменения пересчитываются на Idle, когда AutoCAD свободен. Ошибка автоматического пересчёта присутствует в контексте. Старые произвольные поля DWG, отсутствующие в графе CAD MCP, не объявляются проверенными на циклы.

Новые C# действия:

- `solid_loft`: 2–30 замкнутых профилей, необязательные направляющие либо траектория; `ruled` задаёт линейчатую поверхность. Селектор содержит один `handle` или ранний `target`.
- `cad_solid_get`: объём, рёбра и грани BRep. Их индексы используют `solid_fillet`, `solid_chamfer`, `solid_shell`; после изменения топологии индексы надо перечитать. `solid_section` создаёт штатный Region сечением тела плоскостью.
- `assembly_create/update`: штатные блоки и тела для `beam`, `column`, `screw_pile`, `stairs`, `railing`, `rebar`, `steel_joint`; параметры, марки, материал и плотность сохраняются в Xrecord. Обновление пересоздаёт геометрию и подписи. Общая для нескольких вставок дефиниция не обновляется без выделения отдельной копии.
- `assembly_schedule`: штатная ведомость параметрических элементов. Длина, марка, материал и масса обновляются после изменения сборки. Требуются известные единицы DWG. Масса винтовой сваи включает ствол; сетка лопасти исключена и обозначена в ведомости. Арматурные прямые сегменты могут пересекаться в узлах; радиусы гибки и точная масса требуют уточнённой геометрии. Все шаблоны — геометрия и ведомости, без автоматического расчёта несущей способности.

Пример балки, координаты и размеры в единицах DWG:

```json
[{"op":"assembly_create","id":"beam","kind":"beam","position":[0,0,0],"parameters":{"length":5000,"width":200,"height":300,"web_thickness":8,"flange_thickness":12},"mark":"Б1","material":"09Г2С"}]
```

Civil 3D: дополнены существующие TIN операции, создание трассы прямыми XY-сегментами, добавление сегмента, проектный профиль с касательными по станции/отметке, профиль поверхности, сеть с каталогом деталей, трубы и колодцы, ограниченный набор свойств. Имена стилей/слоёв и handles каталога деталей берут из текущего продукта. `cad_vertical_capabilities` показывает фактически загруженную версию API и сигнатуры; отсутствующий API явно отклоняется. Геометрия Civil создаётся через его managed API в транзакции; произвольный код не исполняется. Подключённые объекты Data Shortcuts не редактируются.

Map 3D: назначение системы координат и штатные OD таблицы/записи, типы Character, Integer, Real, Point. Назначение системы координат само по себе не перепроецирует существующую геометрию. Map действия исполняются по одному с резервной копией: собственные транзакции Map не объявляются атомарными вместе с обычным пакетом DWG. После ошибки возможны частичные изменения; агент должен перечитать объект. Эти новые вертикальные действия пока не проверены в живом Civil 3D/Map 3D и требуют проверки в соответствующем продукте.

Экспорт диалога и выбранного ответа в DOCX сохраняет таблицы Word, изображения и поддерживаемую LaTeX запись в редактируемых формулах OMML: дроби, корни, индексы, греческие символы, матрицы, выравнивание уравнений. Неизвестная команда даёт явную ошибку, без молчаливой подмены формулы картинкой. Выходной файл заменяется только после успешного полного экспорта. Вкладки автоматически следуют теме AutoCAD.
