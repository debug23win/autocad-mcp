# Attachments and internet references

Attach up to 10 files per message by dragging from Explorer or using Attach file. The × button removes an attachment before sending. Source files are not deleted, imported into the working DWG, or overwritten.

- PNG/JPEG/WebP/GIF: up to 7 MiB per image, 21 MiB total.
- Text: source files up to 512 KiB are included in the prompt. Supported encodings: UTF-8, UTF-16 with BOM, Windows-1251. The combined UTF-8 text sent from text files and DOCX documents is limited to 1 MiB per message.
- DOCX: up to 32 MiB per file, with up to 512 KiB of extracted UTF-8 text. CAD MCP reads the attached document locally before sending the message; every provider receives the resulting text in the attachment manifest. Claude does not need to open the binary DOCX or search its containing folder. Paragraphs, runs, tabs and line breaks are retained; tables have explicit `[Table]`, `[Row]` and `[Cell]` boundaries, including multiple paragraphs per cell. Referenced headers, footers, footnotes and endnotes are included with labels after the body. Inserted text and saved field results are read; deleted/moved-from text and field instructions are omitted. The source document is not changed and Microsoft Word is not required.
- DOCX extraction is a text view, not a rendered page: automatic list numbering, exact pagination/style, merged-cell layout, images, charts, equations, embedded files and external linked content are not interpreted. Images are not OCRed, fields are not updated, and hyperlinks are not followed. For those details, attach an exported PDF or page images. An image-only DOCX can have no extractable text. Password-protected DOCX, legacy `.doc` and macro-enabled `.docm` are not supported by this reader.
- PDF: `cad_pdf_read` extracts text and renders actual page images without Adobe Reader/Poppler. Up to 100 MiB, one page per call; continue with `next_page`/`next_text_offset`. `render=true` attaches a PNG; `attach=false` retains only the local file. For scans and copy-restricted PDFs, read the images visually: an empty text layer does not imply an empty page.
- A PDF opening password requires `password` or already decrypted page images. Rendering cannot bypass encryption. Passwords are excluded from response metadata.
- DWG/DXF: `cad_file_inspect` reads a separate AutoCAD database without opening a tab or saving, up to 200 MiB. It returns an outline and entity pages with coordinates, text, dimensions, lengths, and radii. Parameters: `scope=model/layout/layouts/all`, `layout_name`, exact `layer`, `offset`/`limit`, `next_offset`. This is the last saved state; nested/xref/proxy geometry may be incomplete.
- Other formats are passed as paths. Receiving a path does not prove its contents were read; report limitations explicitly.

DWG/DXF requires an AutoCAD worker. Arguments retain the working project's document_id; path selects only the reference file. PDF reading runs in the host independently of CAD UI-thread availability. Local readers accept local/mapped drives and reject UNC/device paths.

DOCX validation bounds both the ZIP metadata and the bytes actually read: at most 2,048 package entries, 64 MiB of total expanded content, 16 MiB per document XML part, 1 MiB per relationship/content-type part, and XML depth 128. DTDs and external entities are prohibited. Package relationships resolve only inside the captured ZIP; no package part is extracted to disk and external document parts are rejected. Invalid, unsupported or oversized documents stop the message with a named-file error instead of silently truncating it or falling back to binary `Read`. Split an oversized document or export the required pages to PDF. The same extraction and limits apply to files added during an active turn. Once captured for a queued input, DOCX/text content remains that input's snapshot even if the original file is later edited or removed; attach it again to send a new version.

`cad_web_download` performs HTTP/HTTPS GET into a unique directory under `%LOCALAPPDATA%\CadMcp\downloads`, up to 100 MiB. It returns the actual path, size, SHA-256, and reader. Redirects are bounded; partial files are removed on failure. Downloads are not executed and working files are not overwritten.

The attachment manifest lists exact file names and absolute paths. Providers use the included text or the indicated reader directly; finding an attached file does not require `Glob`, a search of neighboring files, or a directory grant for its parent. For example, a DOCX attached from `C:\Users\debug\Downloads\!Школа 1360` is read from its exact selected path. Attaching it does not grant access to the whole project directory or to `Downloads`.

The Codex primary has write access to the selected workspace and network access. Claude Read receives rules for specific attachments that still need a file reader; PDF/DWG/DXF also use MCP, including follow-ups during a turn. Text already included in the manifest needs no native file-read permission. Assistants do not gain CAD write permission. File and website contents are reference data, not instructions.

Codex Computer Use requires an available tool and the user's application grant in the panel's Computer Use access dialog. The grant is process/thread scoped and does not edit global Codex settings. Prefer native CAD APIs, readers, and web downloads. This permission neither installs a missing computer-use tool nor removes assistants' read-only restrictions.

Downloads have a 90-second deadline covering redirects, headers and body, plus a 30-second body inactivity timeout. `DOWNLOAD_TIMEOUT` removes partial output; caller cancellation remains cancellation. A byte cap alone does not bound a stalled HTTP response.
