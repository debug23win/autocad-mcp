# Редактирование DWG

Панель разрешает инструменты локального CAD MCP при запуске каждого процесса Codex, включая продолжение сессии. `approvalPolicy=never` отключает дополнительные диалоги; отдельный `mcp_servers.cad.default_tools_approval_mode="approve"` и настройки `cad_edit`/`cad_lisp`/`cad_focus` разрешают сами инструменты изменения. Файловая песочница остаётся `read-only`. Общая конфигурация пользователя не редактируется. Эти настройки относятся к нашей панели; внешний MCP-клиент использует собственную политику доступа.

Основание настройки — [официальный справочник OpenAI](https://learn.chatgpt.com/docs/config-file/config-reference).

Вызовы выбирают session/document из свежего `cad_context`. Нативный инструмент принимает `operation_id` и `operations_json`. Координаты — WCS, значения — единицы DWG, углы — градусы вокруг WCS Z. Справка контракта — `cad_edit_help`.

```json
[
  {"op":"layer","name":"Сеть","color_index":3},
  {"op":"line","id":"pipe","start":[0,0,0],"end":[100,0,0],"layer":"Сеть"},
  {"op":"text","position":[0,5,0],"text":"Трубопровод","height":2.5,"layer":"Сеть"},
  {"op":"move","target":"pipe","displacement":[0,50,0]}
]
```

Поддерживаются 42 операции. Для 3D в их числе `polyline3d`, `spline`, `mesh`, `sphere`, `cone`, `wedge`, `torus`, `extrude`, `sweep`, `revolve`, `solid_boolean` и `rotate3d`. Полный актуальный список и поля возвращает `cad_edit_help`.

`id` связывает созданную сущность с последующим `target` в пакете. Имеющиеся объекты задаются через `handle`. Слои, блоки, стили и типы линий читаются через `cad_catalog`. Вставка блока использует существующее определение; новое создаётся нативной операцией `block_define` из существующих объектов. Атрибуты задаются `{ "TAG":"Значение" }`. Для перемещения и поворота блока с атрибутами применяются transform-инструменты. Нативный путь не редактирует xref; для специальных Civil/Map объектов есть только явно перечисленные в справке операции.

Ошибка нативного пакета до commit откатывает весь пакет. Конечные объекты читаются из базы до commit; слишком большой результат откатывается с предложением уменьшить пакет. Дальнейший запрос использует возвращённую ревизию. При включённом Undo и доступном COM-документе пакет объединяется StartUndoMark/EndUndoMark. Существующая пользовательская группа не закрывается плагином. Ответ указывает фактическую доступность группы. После ручного Undo нужно обновить контекст.

`cad_lisp` принимает код до 65536 символов, исполняемый внутри `progn`. Поддерживает несколько выражений и русские строки. Код передаётся через managed callback после повторной проверки документа и ревизии перед запуском. Для команд используйте полностью заданный `command-s`; если команда использует UCS, преобразуйте координаты `trans`.

`queued` подтверждает постановку в очередь. `cad_operation_status` показывает queued/running/completed/failed/not_found и возвращает результат. После AutoLISP нужно отдельно прочитать изменённые объекты или проверить файлы. Callback сам по себе не доказывает корректность геометрии. При ошибке возможны частичные изменения; скрипт может менять Undo-группу и активный DWG. Общий откат внешних эффектов не обещается.

Stop модели не отменяет уже поставленный в очередь скрипт. Для выполняющегося скрипта применяется Esc в AutoCAD. События отмены/ошибки CAD-команды переводят запись в failed с предупреждением о возможных частичных изменениях. Без callback или события завершения журнал может остаться незавершённым; повтор автоматически не запускается.

В 0.3.0 журнал сохраняется в `%LOCALAPPDATA%/CadMcp/operations/<worker-session>`. До запуска сохраняется queued, затем running и результат; в памяти кэшируются последние завершённые записи. Предела в 128 операций больше нет. Повтор точного запроса с прежними `operation_id`, данными и `expected_revision` возвращает прежний результат; другой запрос с тем же id даёт конфликт. Ошибка сохранения после commit не превращает выполненное изменение в «откат»: ответ содержит journal_warning и остаётся в памяти, на диске сохраняется незавершённая запись.

После перезапуска CAD новые идентификаторы сессии/документа не совпадают с прежними. Прежние файлы журнала служат аудитом; not_found в новой сессии не доказывает отсутствие изменения. Повреждённая сохранённая запись запрещает подтверждение безопасного повтора. Перед повтором неизвестного результата проверить чертёж.
