# Редактирование DWG

Панель разрешает инструменты локального CAD MCP при запуске каждого процесса Codex, включая продолжение сессии. `approvalPolicy=never` отключает дополнительные диалоги; отдельный `mcp_servers.cad.default_tools_approval_mode="approve"` и настройки `cad_edit`/`cad_lisp`/`cad_focus` разрешают сами инструменты изменения. Файловая песочница остаётся `read-only`. Общая конфигурация пользователя не редактируется. Эти настройки относятся к нашей панели; внешний MCP-клиент использует собственную политику доступа.

Основание настройки — [официальный справочник OpenAI](https://learn.chatgpt.com/docs/config-file/config-reference).

Вызовы выбирают session/document из свежего `cad_context`. Нативный инструмент принимает `operation_id` и `operations_json`. Координаты — WCS, значения — единицы DWG, углы — градусы вокруг WCS Z. Справка контракта — `cad_edit_help`.

```json
[
  {"op":"layer","name":"Сеть","color_index":3},
  {"op":"line","id":"pipe","start":[0,0,0],"end":[100,0,0],"layer":"Сеть"},
  {"op":"text","position":[0,5,0],"text":"Трубопровод","height":2.5,"layer":"Сеть"},
  {"op":"move","target":"pipe","displacement":[0,50,0]}
]
```

Поддерживаются 95 операций. Для 3D в их числе `polyline3d`, `spline`, `mesh`, `sphere`, `cone`, `wedge`, `torus`, `extrude`, `sweep`, `revolve`, `solid_boolean` и `rotate3d`. Полный актуальный список и поля возвращает `cad_edit_help`.

## Повседневные операции 2D

Геометрия считается нативно, без командной строки, поэтому ошибка в любой операции откатывает весь пакет.

| Операция | Что делает |
|---|---|
| `text_replace` | Замена текста в TEXT, MTEXT и значениях атрибутов; по выбору — в размерах, таблицах и определениях блоков. В MTEXT меняются только участки текста между кодами форматирования: шрифт, цвет, дроби и абзацы сохраняются. Ø, ° и ± в поиске совпадают и с кодами `%%c`, `%%d`, `%%p`; внутри самих кодов (`%%c`, `%%nnn`, `\U+XXXX`) совпадение не ищется. Поля, формулы, скрытые ячейки объединённых диапазонов таблиц и объекты на заблокированных слоях пропускаются и подсчитываются |
| `offset` | Смещение отрезка, дуги, окружности, полилинии, эллипса или сплайна; `side_point` выбирает сторону — ту, где точка лежит относительно ближайшей точки кривой; если с этой стороны смещение построить нельзя, операция отклоняется |
| `explode` | Расчленение объекта; для блоков значения атрибутов становятся текстом (как BURST), иначе остаются определения атрибутов (как EXPLODE). Вложенные блоки сохраняют значения своих атрибутов |
| `join` | Объединение кривых, сходящихся конец в конец; отрезок или дуга в основе превращаются в полилинию |
| `array_rect`, `array_polar` | Прямоугольный и круговой массивы обычных копий, не более 2000 копий; круговой массив без поворота перемещает выбор целиком вокруг его общего центра |
| `fillet`, `chamfer` | Скругление (радиус 0 — острый угол) и фаска двух отрезков в плоскости XY |
| `trim`, `extend` | Обрезка по границам, как команда ОБРЕЗАТЬ: удаляется только участок между пересечениями по обе стороны от указанной точки; удлинение до ближайшей границы (прибавленная длина измеряется по кривой) |
| `dimension_angular`, `mleader` | Угловой размер по трём точкам и мультивыноска с текстом |
| `field_text` | MTEXT с живым полем длины, площади, радиуса и других свойств объекта; `factor` переводит единицы (0.000001 — мм² в м²) |
| `xref_attach`, `block_import` | Вставка внешней ссылки и копирование определений блоков из другого DWG. Они действуют вне транзакции правки, поэтому отправляются отдельным запросом (иначе `SINGLE_OPERATION_REQUIRED`) |
| `layer_merge` | Перенос объектов (и атрибутов) со слоёв-источников на целевые слои во всех листах и определениях блоков, с удалением опустевших слоёв. Слой 0 внутри блоков не трогается |
| `xdata_set`, `xrecord_set` | Расширенные данные приложения (до 16 КБ, строки до 255 символов без переносов) и записи XRecord в словаре расширения объекта или в словаре чертежа. Имена приложений и словарей AutoCAD и вертикальных продуктов (`ACAD*`, `ACDB*`, `AEC*`, `ADSK*`, `AUTODESK*`, `ACMAP*`) отклоняются с `RESERVED_NAME`; удаление по ключу стирает только запись данных |

`solid_boolean` сообщает объёмы до и после; операция, которая оставила бы пустое тело, отклоняется с `EMPTY_SOLID_RESULT`. Перед массовыми и разрушающими операциями (`text_replace`, `layer_merge`, `explode`, `trim`, `join`, `block_import`) сохраняется контрольная копия DWG.

Пакет, затронувший больше 250 объектов, больше не отклоняется проверкой качества: отчёт помечается `REVIEW_SKIPPED`, а очень большой список прочитанных объектов сокращается (`entities_truncated`), при этом критерии приёмки по-прежнему проверяют все объекты, а `changed_handles` перечисляет все изменённые объекты (по нему работают `cad_verify` с `operation_id` и список квитанций). Отчёт качества только описывает результат: сбой внутри него помечается `REVIEW_FAILED` и никогда не отменяет правку.

## Пробный прогон

`cad_edit_preview` выполняет тот же план в транзакции, которая всегда откатывается: возвращает результаты, прочитанные объекты, отчёт качества и проверку `expectations_json` (провал не прерывает просмотр, а показывается). Чертёж не меняется, шаг отмены не появляется; handles в ответе временные. Ответ содержит `plan_hash`: `cad_edit` с тем же планом и критериями, `preview_hash` и `expected_revision`, равной `previewed_revision`, выполнит ровно просмотренный план; изменённый план, другой чертёж или изменившийся чертёж дают `PREVIEW_MISMATCH`. Хэш подписан секретом рабочего процесса AutoCAD, поэтому получить его можно только просмотром. Просмотр, как и правка, делает свой чертёж активным. Листы, видовые экраны, растры, внешние ссылки, импорт блоков и операции Civil/Map просмотреть нельзя: их действие выходит за транзакцию чертежа. Флаг DBMOD после просмотра может показать чертёж изменённым — состояние до просмотра возвращается в `document_state_before_preview`. Помощникам только для чтения просмотр недоступен.

Код и справка: `src/CadMcp.Core/ModifyPlan.cs`, `src/CadMcp.AutoCAD/ModifyOperations.cs`, `cad_edit_help`. Проверка планов, замены текста и хэша плана покрыта модульными тестами; сами операции в работающем AutoCAD ещё не проверялись.

`id` связывает созданную сущность с последующим `target` в пакете. Имеющиеся объекты задаются через `handle`. Слои, блоки, стили и типы линий читаются через `cad_catalog`. Вставка блока использует существующее определение; новое создаётся нативной операцией `block_define` из существующих объектов. Атрибуты задаются `{ "TAG":"Значение" }`. Для перемещения и поворота блока с атрибутами применяются transform-инструменты. Нативный путь не редактирует xref; для специальных Civil/Map объектов есть только явно перечисленные в справке операции.

Ошибка нативного пакета до commit откатывает весь пакет. Конечные объекты читаются из базы до commit; слишком большой результат откатывается с предложением уменьшить пакет. Дальнейший запрос использует возвращённую ревизию. При включённом Undo и доступном COM-документе пакет объединяется StartUndoMark/EndUndoMark. Существующая пользовательская группа не закрывается плагином. Ответ указывает фактическую доступность группы. После ручного Undo нужно обновить контекст.

## AutoLISP: решение за пользователем

Перед выполнением `cad_lisp` код проверяется сканером: запуск программ и COM-объектов, запись файлов и реестра, загрузка кода (`load`, `NETLOAD`, `APPLOAD`), код, собираемый на лету (`eval`/`read`), реакторы. Команды, которые открывают, закрывают или переключают чертежи, отклоняются всегда. Сканер лишь предупреждает: список запретов обходится, поэтому решение принимает пользователь.

Политика задаётся командой `CADMCPLISP` или выбором в панели чата и хранится в `%LOCALAPPDATA%/CadMcp/settings.json`; агент изменить её не может: скрипт, упоминающий `CADMCPLISP`, отклоняется, команда отказывается работать во время скрипта агента, а ослабление политики командой требует нажатия кнопки в окне подтверждения.

| Политика | Поведение |
|---|---|
| `ask` (по умолчанию) | AutoCAD показывает код и найденные риски в отдельном окне; агент получает `waiting_for_user_confirmation_in_AutoCAD` и ждёт через `cad_operation_status`. Отказ — `LISP_DENIED`, нет ответа 10 минут — `LISP_APPROVAL_TIMEOUT` |
| `auto_safe` | Код без рискованных находок выполняется сразу, остальной требует подтверждения |
| `allow` | Выполняется без подтверждения |
| `deny` | Отклоняется с `LISP_DISABLED` |

Переменная окружения `CAD_MCP_LISP_POLICY` имеет приоритет — для автоматических прогонов. Флажок «Не спрашивать до перезапуска AutoCAD» в окне подтверждения включает `auto_safe` до конца сеанса или до следующего выбора политики (в том числе в панели чата). На время скрипта отключаются объектные привязки (бит 16384 OSMODE), FILEDIA и CMDDIA равны 0; исходные значения восстанавливаются, если скрипт не установил эти переменные сам.

Подтверждённый скрипт запускается при ближайшем простое AutoCAD, когда его чертёж активен и не выполняется команда; если за время ожидания чертёж изменили, скрипт не запускается (`REVISION_CONFLICT`). Пока скрипт ждёт подтверждения, другие правки получают `BUSY_LISP` с объяснением. Опции вроде `"_Close"`, `"_New"` или `"_eXit"` после незавершённой команды не блокируются, а показываются пользователю как возможное переключение чертежей; `command-s` и формы с `.` или `-` (`"_.CLOSE"`) по-прежнему отклоняются. Сканер также отмечает внешние команды из acad.pgp (`START`, `DEL` и другие), запись файлов (`SAVEAS`, `WBLOCK`, `PLOT`…), `atoms-family`, `SendCommand`/`PostCommand` и методы документа через `vlax-invoke`, изменение `SECURELOAD`/`TRUSTEDPATHS`.

`cad_lisp` принимает код до 65536 символов, исполняемый внутри `progn`. Поддерживает несколько выражений и русские строки. Код передаётся через managed callback после повторной проверки документа и ревизии перед запуском. Для команд используйте полностью заданный `command-s` с глобальными именами команд и опций через подчёркивание (`"_.-LAYER"`, `"_C"`): русская версия AutoCAD не принимает английские имена без него. Если команда использует UCS, преобразуйте координаты `trans`.

`queued` подтверждает постановку в очередь. `cad_operation_status` показывает queued/running/completed/failed/not_found и возвращает результат. После AutoLISP нужно отдельно прочитать изменённые объекты или проверить файлы. Callback сам по себе не доказывает корректность геометрии. При ошибке возможны частичные изменения; скрипт может менять Undo-группу и активный DWG. Общий откат внешних эффектов не обещается.

Stop модели не отменяет уже поставленный в очередь скрипт. Для выполняющегося скрипта применяется Esc в AutoCAD. События отмены/ошибки CAD-команды переводят запись в failed с предупреждением о возможных частичных изменениях. Без callback или события завершения журнал может остаться незавершённым; повтор автоматически не запускается.

В 0.3.0 журнал сохраняется в `%LOCALAPPDATA%/CadMcp/operations/<worker-session>`. До запуска сохраняется queued, затем running и результат; в памяти кэшируются последние завершённые записи. Предела в 128 операций больше нет. Повтор точного запроса с прежними `operation_id`, данными и `expected_revision` возвращает прежний результат; другой запрос с тем же id даёт конфликт. Ошибка сохранения после commit не превращает выполненное изменение в «откат»: ответ содержит journal_warning и остаётся в памяти, на диске сохраняется незавершённая запись.

После перезапуска CAD новые идентификаторы сессии/документа не совпадают с прежними. Прежние файлы журнала служат аудитом; not_found в новой сессии не доказывает отсутствие изменения. Повреждённая сохранённая запись запрещает подтверждение безопасного повтора. Перед повтором неизвестного результата проверить чертёж.
