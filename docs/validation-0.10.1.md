# Проверка 0.10.1-preview — 6 октября 2026

Исправлены четыре проблемы чтения: контекст неактивного DWG, привязка листа к области модели, интерпретация размеров и превью бумажного пространства.

## Поведение

- `cad_context` читает базу неактивного DWG без обращения к недоступному текущему виду редактора. Отсутствующие UCS/selection/view отмечены явно; чтение не переключает вкладку.
- `cad_catalog` и `cad_entity_get` возвращают название пространства, центры видового экрана в DCS/WCS, поворот, границы проекции и замороженные слои. Общий экран бумаги отделён от экранов модели; номер `-1` не считается доказательством отсутствия вида.
- `cad_search` поддерживает точный `layout_name` и `scope=viewport`. Геометрия без доступных extents исключается из ограниченного поиска, а количество таких исключений и ограничение покрытия возвращаются агенту.
- Размеры возвращают эффективный стиль, исходную геометрию, native Measurement, коэффициент и текст из существующего размерного блока. Коэффициент не применяется повторно: native Measurement уже может включать DIMLFAC. Чтение не регенерирует размерный блок; его сохранённая надпись может требовать проверки актуальности. INSUNITS не заменяет проверку проектных единиц.
- Превью использует отдельную копию базы в памяти (`ForceWblockDatabaseCopy` / `Wblock`) и offscreen GraphicsSystem. Листы собираются из штатной геометрии бумаги и видов модели с координатами, масштабом, поворотом и VP-frozen слоями. Перед каждым кадром выполняется консервативный отбор по проекции extents. Превью использует явный стиль 2D Wireframe. Камера рабочего DWG не меняется. Для тяжёлого превью транспорт ждёт до 90 секунд; прочие вызовы сохраняют предел 30 секунд.

## Подтверждённые проверки

В Map 3D 2025, запущенном пользователем вручную, `ReadingProbe` проверил 26 условий: контекст фонового документа, выбор листа, viewport search, геометрический размер 4.2 с DIMLFAC 1000 → native значение и надпись 4200, отрицательный коэффициент в модели и бумаге, текстовая подмена, семь изображений, сохранение DBMOD/ширины текущего вида. Каталог и контекст трёх реальных тестовых копий КЖ2 прочитаны из фоновых вкладок. Частные DWG не входят в репозиторий и установщик.

Реальный подписной Codex подтвердил лист входной группы №2, расстояние 4200, общий размер проступей 2400 и толщину плиты 200. Он корректно обнаружил конфликт INSUNITS=метры с надписью «200 мм» и геометрией фрагмента. Шаг 300 и количество 8 в надписи являются текстовой подменой; каждая проступь этим тестом отдельно не проверена. Первый повторный прогон выявил пустые экраны неактивного листа и попадание вложенных объектов без extents в несколько областей — обе причины устранены в финальном коде. Финальное offscreen-превью реального листа 4.2 получено и визуально проверено: план, А–А, Б–Б, спецификация и основная надпись присутствуют. На этом компьютере кадр 1000×700 занял около 48 секунд; тяжёлые штриховки остаются ограничением скорости.

Финальный подписной прогон выполнил 9 MCP-вызовов без ошибок: контекст неактивного DWG, три штатных размера, связанный текст, штатная таблица 6×6 со всеми 36 ячейками, превью и повторный контекст. Агент получил PNG как изображение через MCP и правильно перечислил видимые части листа. Изменений, сохранения и переключения рабочего документа агент не выполнял.

Обычные автоматические тесты протокола, Word, подписных провайдеров и доступа прошли 57 сценариев. Все три тестовые копии закрыты без сохранения; их SHA-256 совпали с исходными копиями. Вернулся исходный пользовательский DWG, в котором 0 объектов в Model/Paper. Его DBMOD после возвращения изменился с 0 на 1; причина этого флага в окружении с установленной старой версией и диагностическими сборками не установлена. Флаг не сбрасывался и пользовательский документ не сохранялся. Сохранение DBMOD=0 подтверждено для отдельного fixture offscreen-превью, а не для всего пользовательского сеанса.

Подписной доступ Claude в этом прогоне не проверялся. Поддержка SDK других выпусков проверяется сборкой; GUI этой проверки — только Map 3D 2025.

## Ограничения превью

Изображение не является подтверждением печати: CTB/STB, белые маски, перекрывающиеся экраны и точная видимость выключенных экранов требуют проверки опубликованного PDF. Непрямоугольная граница аппроксимируется по native кривой; неподдерживаемые границы и перспективные экраны отмечаются явно. Для точного pixel/WCS соответствия нужна регистрация изображения по контрольным точкам.

Воспроизведение КЖ/КМ целиком, геометрическая проверка каждой ступени, структурный расчёт и нормативная проверка этим этапом не подтверждаются.

## Повторение локального теста

`tests/CadMcp.GuiProbe/ReadingProbe.cs` компилирует production-код в отдельную сборку. Файл `probe-config.json` рядом с DLL задаёт `output` и массив `drawings` — полные пути уже открытых **тестовых копий** DWG. Команда `CADMCPREADBENCH011O` создаёт свой отдельный fixture, записывает проверки и изображения в output, оставляет собственный pipe для проверки MCP. Команда `CADMCPREADBENCHSTOP011O` выключает только этот канал и закрывает только собственный fixture. Частные пути и файлы задаются вне репозитория.
