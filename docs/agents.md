# Assistants and parallel work

The Assistants setting supports Codex and Claude Code. It allows up to three assistants by default; choose two, four, or disable them. Model and reasoning selections are saved separately per provider. Sign in and Diagnostics use the selected official CLI. Users can explicitly delegate tasks, such as reading a profile, checking geology, and independently reviewing sections. The primary agent combines findings, edits the DWG, and shows the final view.

For Codex, the panel passes `agents.enabled` and `agents.max_concurrent_threads_per_session` to the local app-server. For Claude Code, it supplies a temporary `cad_researcher` definition through `--agents` and limits concurrent assistants with `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`. This assistant has CAD read tools only: no editing, AutoLISP, or export. Both the Claude primary and researcher can also use `WebSearch` and read workspace files/attachments through `Read`, `Glob`, and `Grep`. Other built-in tools, including shell execution and file writing, are unavailable. Both providers use their official CLI subscription login; more assistants consume more model allowance.

The broker accepts concurrent connections, so a long CAD command does not block connection checks. Session discovery is also concurrent. Within one AutoCAD process, database access is serialized on its main thread, as required by the CAD API and to prevent conflicting edits. Assistants accelerate independent analysis and review; four requests to one DWG do not become four parallel transactions.

The chat shows a short status, the primary agent's answer, and a final view image when AutoCAD responds. MCP tool-name logs are excluded from the conversation, history, and Word. A missing preview is marked unverified. An image proves neither disk persistence nor geometric accuracy.

Since 0.10.0, the primary Codex chat registers its ID before a task starts. The MCP host checks the official CLI's `threadId`: other or unknown chats are read-only, even if a built-in `worker` inherits the primary connection. Separate read-only configurations also cover built-in and discovered user roles. Claude starts as `cad_primary`, allowing only `cad_researcher`; the researcher has a separate MCP host with `CAD_MCP_READ_ONLY=1` and a read-tool allowlist. The server blocks edits, AutoLISP, export, selection, and cancellation. `cad_context.access` reports effective access.

With assistants enabled, the primary agent requests independent review of complex results, fixes confirmed defects, and rechecks geometry. Provider settings and protocols have automated checks. Real Codex delegation was tested; a Claude subscription check on the development machine returned HTTP 403 because its organization disabled subscription access to Claude Code.

Each open DWG has its own tab, history directory, provider instance, and task owner. Models can work concurrently across tabs. MCP inherits the session/document IDs and blocks requests to another DWG, including rendering. Stop cancels only that tab owner's operations; subagents inherit its document. Open/closed files refresh every five seconds. Tab tooltips show the DWG path, which supplies a new chat's working directory. Save As retains the conversation until the tab closes; reopening selects history using the new path. Identically named files in different directories have separate histories.
