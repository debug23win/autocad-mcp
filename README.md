# CAD MCP — AutoCAD, Map 3D and Civil 3D 2025–2027

**English** | [Русский](README.ru.md)

Version 0.11.1-preview. An open-source MCP server and chat interface for a running AutoCAD instance. New code is licensed under Apache-2.0; licenses for adapted code and dependencies are listed in [NOTICE](NOTICE), [docs/provenance.md](docs/provenance.md) and [licenses/](licenses/).

See [CHANGELOG.md](CHANGELOG.md) for release changes and validation results, and [docs/validation.md](docs/validation.md) for the validation procedure. Detailed documentation linked below is currently in Russian.

Version 0.11.1 fixes TEXT lines from different spaces, block definitions or Z elevations being grouped together, and refreshes dynamic block references after `text_replace`. Old composite keys that combine unrelated text are rejected without changing the DWG. These fixes were checked in AutoCAD 2025 Core Console; the full Map 3D/Civil 3D interface still requires separate validation. [Release validation](CHANGELOG.md#0111-preview).

Version 0.11.0 adds user approval for AutoLISP, edit previews (`cad_edit_preview`), everyday 2D operations (trim, extend, fillet, offset, arrays, text replacement, fields and external references), Properties palette reads (`cad_properties`), proxy inspection (`cad_proxies`), text translation and fitting (`cad_text_units`, `text_translate`, `text_fit`), polyline corner rounding (`polyline_fillet`), drawing summaries and quantity takeoffs (`cad_outline`, `cad_takeoff`), a change feed (`cad_changes`), dimension/font/topology/sheet-set checks, Civil 3D alignments with curves, Civil 3D call validation against 2024–2027 API signatures, Map 3D coordinate-system validation, and an agent evaluation harness. **At the time of the 0.11.0 release, these features had not been tested in running AutoCAD, Civil 3D or Map 3D products.** [Features and validation status](CHANGELOG.md#0110-preview).

Version 0.10.0 adds measurable task criteria, verification of all geometry changed by a response, a steel-section catalog with corner radii, reinforcement bars with circular bends, and solid screw-pile blades. Helpers have read-only access; the primary agent performs edits. Linked-table Redo and PDF verification during background plotting were also fixed. [Features, limitations and release validation](CHANGELOG.md#0100-preview).

## Features

Version 0.8.0 adds native AutoCAD tables: reading, creation, editing, merged cells, rows/columns, local formulas, and references to cells in other tables through DWG fields. It also adds SPDS dimensions, grid axes and elevation marks; editable borders and title blocks on A0–A4 sheets; schedule/specification forms based on GOST R 21.101-2026; and reinforced-concrete (KZh) and steelwork (KM) schedules. All objects are created through C#. [Contracts, examples and limits of standards checking](docs/spds-tables.md).

You can add instructions and attachments while the agent is working using the **Дополнить** (*Add to task*) button or Enter; Shift+Enter inserts a new line. Codex receives the additional input in the current turn; Claude receives it through the message stream in the same session. A visible receipt confirms delivery, and messages entered while the connection starts remain queued. [Follow-up input](docs/follow-up-input.md).

Version 0.7.0 adds measurable result criteria: `cad_edit` checks actual geometry before commit and rolls back the batch if the criteria fail; `cad_verify` reads objects again after an edit. The panel appends the confirmed result and DWG save status. Lost responses can be recovered from the operation journal without recreating geometry, and operation status remains readable while AutoCAD is busy. Photo-based workflows include calibration from known points, coordinate conversion, comparison against supplied silhouettes, and temporary views framed around selected objects. These help verify an approximate model; they do not automatically reconstruct hidden 3D geometry. Codex and Claude share the same contract. Streaming text display and scroll-position retention were also fixed. [Details and examples](docs/result-verification.md).

There are 46 MCP tools and 98 native action types. In addition to basic geometry, C# creates 3D polylines, splines, arbitrary polygon meshes and solid primitives; extrudes and revolves closed profiles; sweeps solids along paths; performs Boolean unions, subtractions and intersections; and rotates objects around a 3D axis. Sheets and PDF/DXF output also use the AutoCAD C# API. Edits run in a transaction with final-state readback; an error before commit rolls back the batch. When native Undo grouping is available, one Undo reverses the batch. AutoLISP remains a fallback for operations without a native adapter and does not guarantee atomic rollback.

`cad_search` reads the DWG database beyond the limited snapshot. Scopes include the current space, model space, layouts, all spaces, selection and the current view, with filters for layer, type, text and WCS bounds. Nested blocks and loaded xrefs are expanded with instance paths and world-coordinate transforms. Summaries omit full vertex/property data; details are requested separately. Dynamic blocks expose available dynamic properties, and dimensions expose definition points and measurements. Support for special SPDS GraphiCS, Map and Civil properties is explicitly marked as partial.

Catalogs, snapshots and targeted searches are cached by document, revision and space. Selection and view state are read fresh. Large results are stored in a bounded archive with paginated access and marked as historical. Operation records are persisted before execution and after completion. There is no longer a 128-operation limit; only a small cache of completed records remains in memory. If persisting a completed result fails, the response retains the confirmed change information and includes a warning.

The panel shows the active DWG and uses the current selection. Found-object lists and technical `cad_*` messages have been removed from the chat. The HTML conversation renders Markdown, local images and KaTeX formulas, follows AutoCAD's light/dark theme, and shows an available brief reasoning summary and a readable activity status. After a visual CAD operation, the panel attaches a snapshot of the current view; if AutoCAD does not respond, it reports that result verification could not be completed. You can export the entire conversation or a selected response, including images, to Word. Supported formulas become editable OMML equations, and tables become native Word tables. Unsupported notation produces an explicit export error. The panel includes connection checks, Codex sign-in and diagnostics, an error log, model selection and reasoning-effort selection. Enter sends a message; Shift+Enter inserts a new line. History and settings are saved. **Stop** cancels the chat's accepted CAD requests at a safe boundary; an executing native geometry-kernel call finishes first.

Codex and Claude Code share a helper-count setting: disabled, or up to 2–4 helpers. The primary agent delegates independent reading, calculations and review, then performs and verifies the final edit itself. Claude receives a dedicated `cad_researcher` helper restricted to CAD read operations. The local broker accepts concurrent requests and checks independent CAD sessions in parallel. Access to a single DWG database remains sequential on AutoCAD's main thread. [Helpers and parallel execution](docs/agents.md).

Since 0.3.1, files can be dragged into the chat or selected with a button. Attachments are listed before sending and can be removed individually. Small text files are sent with their contents; PNG/JPEG/WebP/GIF files are sent as images through the provider protocol. Other files, including DWG and PDF, are passed as local paths: the agent must have a tool capable of reading them and must explicitly report when it does not. [Attachments](docs/attachments.md).

Version 0.4.0 adds C# creation of block definitions from existing objects, layouts, points and ellipses. PDF/DXF output returns the file size and SHA-256 hash. These operations passed Core Console checks on a blank test DWG in AutoCAD 2025. PDF creation was checked for a nonempty output file; visual sheet correctness requires separate review. For Civil 3D/Map 3D and SPDS, special-object reading includes a limited set of named properties when the corresponding managed assemblies are available; complete geometry and editing still require dedicated API adapters. [Capability diagram and implementation comparison](docs/capabilities.md).

The installer includes Codex 0.159.0. Subscription access uses the official CLI and your own account sign-in. Models are loaded from its catalog, and switching models preserves the conversation. The application's MCP tools are approved automatically within its process, without changing the user's `.codex/config.toml`. Claude Code must be installed and authenticated separately.

Version 0.5.0 adds layouts with viewports at a specified scale, plot settings, layout copying, and batch publication of separate PDFs with JSON/CSV file manifests. PNG/JPEG/TIFF/BMP rasters can be registered to WCS using 3–20 control points and inserted into a DWG; both regular and skewed placements have been checked. View snapshots receive an `image_id`; control points can calibrate their pixels for conversion to WCS and back. Civil 3D support includes catalogs of surfaces, alignments, profiles and networks, elevation sampling, and TIN creation/point insertion. Map 3D support includes coordinate-system, object-data-table and object-data reads when its API is available. Special Civil/Map operations have not yet been tested in running vertical products. See [georeferencing](docs/georeferencing.md), [sheet publishing](docs/publishing.md) and [vertical APIs](docs/verticals.md).

Version 0.6.0 adds native C# operations for 3D meshes, spatial polylines and splines, spheres, cones, wedges, tori, extrusion, sweep, profile revolution, Boolean operations and 3D rotation. These were checked on a test DWG in AutoCAD 2025 Core Console. For photo-based modeling, the agent first breaks the shape into measurable parts and applies these operations; a photograph alone does not define exact dimensions. [3D modeling contract and limitations](docs/native-modeling.md).

## Compatibility

| Products / versions | Adapter | Interface | Validation |
|---|---|---|---|
| AutoCAD, Map 3D, Civil 3D 2025 before the .NET 10 updates | AutoCAD 2025 API, .NET 8 | Ribbon-launched palette | AutoCAD and Map 3D: native GUI checks; Civil 3D not separately tested |
| AutoCAD, Map 3D, Civil 3D 2026 before the .NET 10 updates | Compatible AutoCAD 2025 API, .NET 8 | Ribbon-launched palette | Compiled; live startup not separately tested |
| AutoCAD and AutoCAD-based products 2025.1.4+ | Official AutoCAD.NET 25.0.2, .NET 10 | Ribbon-launched standalone window | Compiled against the SDK; live startup of the updated product not tested |
| AutoCAD and AutoCAD-based products 2026.1.2+ | Official AutoCAD.NET 25.1.1, .NET 10 | Ribbon-launched standalone window | Compiled against the SDK; live startup of the updated product not tested |
| AutoCAD, Map 3D, Civil 3D 2027 | Official AutoCAD.NET 26.0.0, .NET 10 | Ribbon-launched standalone window | Compiled against the official SDK; live startup not yet tested |

AutoCAD LT and versions earlier than 2025 are excluded from the agreed scope. Versions after 2027 are not supported automatically. Base DWG API compatibility does not establish readiness of specialized Civil network operations, Map geodata, GOST/SPDS compliance checks or drawing-set publication.

AutoCAD 2025.1.4 and 2026.1.2 move from .NET 8 to .NET 10. The installer reads `acdbmgd.runtimeconfig.json` for each installed release and selects the appropriate adapter. Run the CAD MCP installer again after updating Autodesk products. If .NET 8 and .NET 10 are mixed within the same product release, installation stops: [Autodesk warns that this configuration can cause crashes](https://help.autodesk.com/view/ACD/2026/ENU/?caas=caas/sfdcarticles/sfdcarticles/AutoCAD-2026-1-2-and-Toolset-Products-Crashes-After-Updating-To-NET-10-Based-Builds.html). Autodesk SDK assemblies are not redistributed in the installer.

## Installation

1. Close AutoCAD, Map 3D, Civil 3D and Core Console. The installer stops the broker, standalone CAD MCP window and bundled Codex processes running from the add-in folder. An active task in the standalone window will be interrupted; save any text you need first. The installer does not close user drawings.
2. Install for the current user. The update destination is `%APPDATA%/Autodesk/ApplicationPlugins/CadMcp.AutoCAD2025.bundle`.
3. Start a supported product. If prompted for trust, approve the specific assembly. There is no need to change `SECURELOAD` globally.
4. Open **CAD MCP → Открыть чат** (*Open chat*) or run `CADMCPCHAT`. For Codex, click **Войти** (*Sign in*); authenticate Claude through its CLI.

An external MCP client starts `Contents/Host/CadMcp.Host.exe` without arguments. The broker starts automatically. The panel is bound to the CAD session that launched it and supplies the active DWG to the agent; tools also validate the document and revision.

User data is stored under `%LOCALAPPDATA%/CadMcp/`: `chat`, `logs/panel.log`, `operations/<worker-session>` and `results/<worker-session>`. Restarting AutoCAD creates new session and document IDs; the previous journal remains available for auditing. An edit with an unknown outcome must not be repeated automatically: inspect the drawing first.

## Building and validation

Windows x64 is required, with a .NET SDK for net8 and a separate SDK for net10. AutoCAD 2025 references can come from an installed AutoCAD instance or, without one, from NuGet: run `scripts/autocad-references.ps1 -Destination <folder>`, then `scripts/build.ps1 -AutoCADDir <folder>`. Lock files and CLI checksums are included. Autodesk DLLs are used for compilation only.

From the repository root, run `scripts/build.ps1`, then `scripts/test.ps1` to execute the xUnit tests in `tests/CadMcp.Tests`; results are written to `artifacts/test-results`. Tests start the built `CadMcp.Host` and fake Codex/Claude processes from `tests/CadMcp.TestCli`; they do not use AutoCAD or real models. GitHub Actions (`.github/workflows/ci.yml`) builds all projects, including adapters and diagnostic programs, with warnings treated as errors and runs the tests for each pull request.

Optional checks with real CLIs, run from the repository root, use `CadMcp.TestCli.exe --live-subagent-test codex|claude <cli>`, `--live-codex-model-test <cli>` and `--live-codex-approval-test <cli>`. For native checks, build `tests/CadMcp.CoreProbe` and run `scripts/test-autocad-core.ps1`; build `tests/CadMcp.NativeProbe` and run `scripts/test-autocad-gui.ps1` (use `-Product MAP` for an installed Map 3D 2025). Core Console uses `/isolate` and a dedicated profile. GUI checks create their own blank DWGs and copy a registered profile beforehand so `/p` does not trigger a modal dialog. The launcher terminates only its own process, restores the previous profile selection if it still points to the test profile, and removes its test profile. Working DWGs are not opened.

To build the installer, first restore Host and Client for `win-x64`, `SelfContained=true`, `RuntimeFrameworkVersion=8.0.31`, and the 2025.1.4+, 2026.1.2+ and 2027 adapters using the .NET 10 SDK. Then run `scripts/prepare-codex.ps1 -Destination <bundle-folder>` and `scripts/build-installer.ps1 -IsccPath <Inno-Setup-6.7.3/ISCC.exe> -CodexDir <bundle-folder> -DotNet2027 <SDK10/dotnet.exe>`.
