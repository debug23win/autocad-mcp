# CAD MCP — прототип чтения для AutoCAD 2025

Локальный результат этапа 3А, 28 сентября 2026. Новый код — Apache-2.0; происхождение заимствований и условия зависимостей: [NOTICE](NOTICE), [аудит](docs/provenance.md).

## Что собрано

- Native worker для установленного AutoCAD 2025.1.2 / .NET 8: выполнение на потоке AutoCAD через очередь Idle, контроль документа и ревизии.
- Локальный broker на именованных каналах текущего пользователя; stdio MCP-сервер на официальном C# SDK. Один broker обслуживает встроенный чат и внешних клиентов.
- Семь инструментов: `cad_sessions`, `cad_context`, `cad_snapshot`, `cad_query`, `cad_entity_get`, `cad_focus`, `cad_render`.
- Чтение линий, окружностей, дуг, полилиний, текста; частичные данные блоков, размеров и неизвестных объектов. Снимки ограничены по объёму и помечают усечение. Поиск работает по материализованному снимку.
- PNG через AutoCAD CapturePreviewImage с метаданными вида; MCP выдаёт отдельный image-блок. Геометрические координаты не выводятся из пикселей.
- Вкладка ленты CAD MCP, палитра чата, потоковый текст, Stop, новые диалоги и экспорт истории. Адаптеры официальных Codex app-server и Claude Code.

**Проверена сборка и автономные протоколы. Загрузка в AutoCAD, работа интерфейса, точность изображения и реальные подписки пока не проверены.**

## Сборка и тесты

Нужны Windows x64, .NET SDK с поддержкой net8.0, .NET 8 Desktop runtime и AutoCAD 2025 с managed DLL. На рабочей машине сборка проверена SDK 9.0.311. Полный CAD должен использовать .NET 8; для обновлений с .NET 10 нужна отдельная проверка.

Из корня репозитория, PowerShell 7:

```powershell
./scripts/build.ps1 -AutoCADDir 'C:\Program Files\Autodesk\AutoCAD 2025'
./scripts/test.ps1
```

Зависимости хранятся в `.runtime/packages`, lock-файлы включены в исходники. Сборка не копирует AutoCAD DLL в результат. Тесты создают только собственные каналы Windows и подставные процессы провайдеров; доступ к AutoCAD, DWG и моделям им не нужен. В ограниченной песочнице именованные каналы могут быть запрещены — тесты выполняются в обычном пользовательском контексте.

Результаты сборки:

- `src/CadMcp.AutoCAD/bin/Release/net8.0-windows/CadMcp.AutoCAD.dll` и соседние CadMcp DLL — расширение CAD.
- `src/CadMcp.Host/bin/Release/net8.0-windows/CadMcp.Host.exe` с соседними зависимостями — broker или MCP stdio host.

## Запуск — только после согласования этапа 3Б

1. Подготовить копию тестового DWG, включая обычные и СПДС GraphiCS объекты. Не публиковать рабочие DWG вместе с исходниками.
2. Запустить broker в отдельном терминале: `CadMcp.Host.exe --broker`. Оставить процесс работающим. Ctrl+C завершает broker.
3. В AutoCAD 2025 выполнить `NETLOAD` для `CadMcp.AutoCAD.dll`; оставить Core и Providers DLL рядом. При запросе AutoCAD о доверии разрешить только конкретную проверенную сборку. Не отключать SECURELOAD глобально.
4. Открыть вкладку **CAD MCP → Открыть чат** или команду `CADMCPCHAT`. Если лента скрыта, команда остаётся доступной.
5. Указать исполняемый файл официального CLI, полный путь к MCP host и рабочую папку. Войти в провайдера штатным способом заранее. Само открытие палитры не запускает CLI и не отправляет данные.
6. При необходимости настроить внешний MCP-клиент на запуск того же host без аргументов. Это отдельный stdio-процесс; его запросы идут в общий broker.

Пример конфигурации Claude Code (заменить путь; файл автоматически не устанавливается):

```json
{"mcpServers":{"cad":{"command":"C:\\path\\to\\CadMcp.Host.exe","args":[]}}}
```

Для внешнего Codex:

```toml
[mcp_servers.cad]
command = 'C:\path\to\CadMcp.Host.exe'
args = []
```

Последовательность ручной проверки: sessions → context → snapshot → query → entity_get → focus → render. Для всех операций над документом передать его session_id, document_id и expected_revision из context. При conflict перечитать контекст и создать новый снимок.

Для остановки испытания закрыть AutoCAD и broker. Расширение не устанавливается в ApplicationPlugins, системные пути доверия и пользовательские MCP-конфигурации скриптами этого проекта не изменяются. На выходе CAD descriptor удаляется; после аварии stale descriptor показывает unreachable, а идентичность сессии предотвращает обращение к новой сессии по старому ID.

## Ограничения v0.1

Чтение ограничено верхним уровнем текущего пространства. Вложенная геометрия блоков/xref, специальные параметры СПДС, семантика сетей, редактирование DWG, выпуск комплектов, LT и вертикальные Civil/Map API пока не реализованы. Map использует только базовый AutoCAD API и требует отдельного живого теста.

`cad_focus` меняет текущее выделение, но не масштабирует вид. `cad_render` — preview API: визуальную точность, текст, СПДС и соответствие текущему виду необходимо проверить на реальных чертежах. Статус результата partial сохраняется до этой проверки. Автоматического восстановления предыдущего выделения пока нет.

Чат — подготовленная оболочка, не завершённый клиент: ещё нет восстановления экспортированной истории, менеджера вложений, карточек объектов, экранов входа и интерактивных запросов провайдеров. Сессия продолжается в пределах работающей палитры. При смене провайдера начинается отдельный диалог.

Официальные CLI остаются внешними программами. Доступ по подписке, передача изображения модели и MCP-операции из реального диалога проверяются на 3Б. Код не извлекает токены. Stop завершает только запущенный оболочкой процесс и его потомков; принятый CAD-запрос может завершиться до своего deadline. Безопасность произвольного исполнения здесь не заявляется: инструменты записи ещё не включены.

## Решение о стеке

На 3А сервис реализован на .NET вместо первоначально предложенного Python. Это позволяет разделять контракты с native worker и UI, использовать уже установленный runtime и не поставлять дополнительный Python. Контракт MCP сохраняет границу для будущих доменных модулей. Инженерную логику из Python-проектов ещё предстоит выборочно перенести или подключить; её наличие сейчас не заявляется.
